# 코드 리뷰 규칙

플랫폼팀의 모든 변경은 PR로 올리고 리뷰를 받은 뒤 머지합니다. `main`에 직접 푸시하는 것은 막혀 있습니다.

## PR 크기

- 한 PR의 변경은 400줄 이하를 권장합니다. 자동 생성 파일(잠금 파일, 마이그레이션 스냅샷)은 세지 않습니다.
- 400줄을 넘으면 PR 설명에 나누지 못한 이유를 적습니다.
- 리팩터링과 기능 추가는 서로 다른 PR로 올립니다.

## 리뷰어와 승인

- 리뷰어는 2명을 지정하고, 그중 1명 이상이 승인하면 머지할 수 있습니다.
- `payment-worker`의 결제 금액 계산과 승인 코드(`payment/amount/`, `payment/approval/` 아래)는 2명 모두 승인해야 합니다.
- 첫 리뷰는 PR이 올라온 뒤 1영업일 안에 답합니다. 바로 볼 수 없으면 "내일 오전에 보겠습니다"처럼 언제 볼지라도 남깁니다.

2026년 4월 중순 전에는 리뷰어 1명 승인이면 결제 코드도 머지할 수 있었습니다. 3월 결제 승인 지연 장애의 회고에서 이 규칙을 바꿨습니다.

## 머지 방식

- squash merge만 씁니다. 머지 커밋 제목은 PR 제목을 그대로 씁니다.
- PR 제목은 `[서비스] 무엇을 했는지` 형식입니다. 예: `[order-api] 주문 취소 시 재고 복구`
- CI가 실패한 PR은 머지할 수 없습니다.

## 리뷰할 때 보는 것

1. 이슈의 완료 기준을 만족하는가
2. 새 동작을 확인하는 테스트가 있는가. 테스트를 지우거나 기대값만 바꿔 통과시키지 않았는가
3. 에러를 잡고 아무 일도 하지 않는 코드가 있는가
4. 이슈와 상관없는 파일을 고쳤는가
5. 비밀 값이 코드나 설정 파일에 들어갔는가

## AI 도구로 만든 코드

AI 코딩 도구를 쓴 PR도 같은 기준으로 리뷰합니다. 작성자는 PR 설명에 AI를 어디에 썼는지 적고, 바뀐 줄을 모두 설명할 수 있어야 합니다. 설명하지 못하는 코드는 리뷰어가 되돌려 보낼 수 있습니다.
