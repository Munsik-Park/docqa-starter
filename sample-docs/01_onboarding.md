# 플랫폼팀 온보딩 가이드

도토리랩 플랫폼팀에 새로 온 사람이 첫 주에 할 일을 정리한 문서입니다. 도토리랩과 이 문서의 사람, 서비스, 수치는 모두 강의용으로 지어낸 것입니다.

## 팀이 맡은 서비스

| 서비스 | 하는 일 | 언어 |
| --- | --- | --- |
| order-api | 주문 생성, 조회, 취소 API | Python, FastAPI |
| payment-worker | 결제 요청을 큐에서 꺼내 결제 대행사로 보냄 | Python |
| admin-web | 운영자용 주문 관리 화면 | TypeScript, React |

세 서비스는 모두 `dotori/platform` 모노레포에 있습니다.

## 첫날

1. 사내 메일 계정으로 GitHub 조직 `dotori-lab` 초대를 수락합니다.
2. 노트북은 IT 담당에게서 받습니다. 지급 노트북은 macOS이고, Linux를 원하면 팀장에게 미리 말합니다.
3. Slack에서 `#plat-team`(팀 채널)과 `#plat-help`(질문 채널)에 들어갑니다.
4. 버디를 배정받습니다. 버디는 첫 2주 동안 리뷰와 질문을 먼저 받아 주는 동료입니다.

## 첫 주

- 개발 환경을 만들고 order-api 테스트를 로컬에서 통과시킵니다.
- `good-first-issue` 라벨이 붙은 이슈 하나를 골라 첫 PR을 올립니다.
- 코드 리뷰 규칙과 배포 런북을 읽습니다.
- 금요일 오후 팀 회고에 참여합니다.

## 권한

| 권한 | 받는 시점 | 요청할 곳 |
| --- | --- | --- |
| GitHub 쓰기 권한 | 첫날 | 팀장 |
| 스테이징 서버 접속 | 첫 주 | `#plat-help` |
| 운영 DB 읽기 권한 | 입사 30일 뒤, 보안 교육 이수 후 | 보안 담당 박지호 |
| 운영 배포 권한 | 첫 배포를 버디와 함께 한 뒤 | 팀장 |

운영 DB 쓰기 권한은 개인에게 주지 않습니다. 데이터 수정이 필요하면 마이그레이션 PR로 합니다.

## 질문할 곳

- 개발 환경, 빌드, 테스트: `#plat-help`
- 배포, 인프라: DevOps 담당 이도현
- 보안, 권한: 보안 담당 박지호
- 그 밖의 일: 버디, 그다음 팀장 김서윤

답이 문서에 없으면 질문한 뒤 이 문서에 직접 추가하는 것이 팀 규칙입니다.
