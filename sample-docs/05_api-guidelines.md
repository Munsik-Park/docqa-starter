# API 설계 규칙

플랫폼팀이 만드는 HTTP API가 따르는 규칙입니다.

## 경로

- 모든 경로는 `/v1`로 시작합니다. 호환이 깨지는 변경만 `/v2`를 새로 만듭니다.
- 자원 이름은 복수형 소문자, 단어 사이는 하이픈입니다. 예: `/v1/orders`, `/v1/refund-requests`
- 동작은 HTTP 메서드로 나타냅니다. 경로에 `create`, `delete` 같은 동사를 넣지 않습니다. 예외는 상태를 바꾸는 동작 하나뿐입니다: `POST /v1/orders/{id}/cancel`

## 목록 조회

- 페이지 크기 `limit`의 기본값은 20, 최대값은 100입니다. 100을 넘게 요청하면 400 에러를 돌려줍니다.
- 다음 페이지는 오프셋이 아니라 커서로 넘깁니다. 응답의 `next_cursor`를 다음 요청의 `cursor`에 넣습니다. 마지막 페이지에서는 `next_cursor`가 `null`입니다.

## 에러 응답

에러는 모두 같은 모양으로 돌려줍니다.

```json
{
  "error": {
    "code": "ORDER_NOT_FOUND",
    "message": "주문을 찾을 수 없습니다.",
    "request_id": "req_8f2c1a"
  }
}
```

- `code`는 대문자와 밑줄로 쓰고, 클라이언트가 분기할 때 씁니다. 한번 정한 코드는 바꾸지 않습니다.
- `message`는 사람이 읽는 설명입니다. 클라이언트가 이 문장으로 분기하면 안 됩니다.
- 내부 예외 메시지나 스택 트레이스를 응답에 넣지 않습니다.

## 시간과 금액

- 시간은 ISO 8601, UTC로 주고받습니다. 예: `2026-07-10T03:00:00Z`
- 금액은 원 단위 정수로 다룹니다. 부동소수점을 쓰지 않습니다.

## 문서

API를 추가하거나 바꾸면 같은 PR에서 OpenAPI 문서도 고칩니다. FastAPI가 만드는 `/docs` 화면이 기준 문서입니다.
