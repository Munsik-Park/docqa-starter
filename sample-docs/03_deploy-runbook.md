# 배포 런북

order-api, payment-worker, admin-web을 운영 환경에 배포하는 순서입니다.

## 배포할 수 있는 때

- 화요일부터 목요일, 10:00부터 16:00 사이에만 배포합니다.
- 금요일, 공휴일 전날, 월말 마지막 영업일에는 배포하지 않습니다. 월말에는 정산 작업이 몰리기 때문입니다.
- 장애를 고치는 핫픽스는 시간 제한이 없습니다. 대신 팀장이나 온콜 담당의 승인을 받습니다.

## 순서

1. `main`의 최신 커밋에 CI가 통과했는지 확인합니다.
2. `#plat-deploy` 채널에 배포할 서비스와 PR 번호를 올립니다.
3. 스테이징에 먼저 배포하고, 스모크 테스트(`make smoke ENV=staging`)를 돌립니다.
4. 스모크 테스트가 통과하면 운영에 배포합니다. 운영 배포는 카나리 방식으로, 트래픽 10%에 15분 동안 먼저 보냅니다.
5. 15분 동안 에러율이 1%를 넘지 않으면 100%로 넓힙니다.
6. 배포가 끝나면 `#plat-deploy`에 완료를 남깁니다.

## 롤백

다음 중 하나라도 보이면 바로 롤백합니다. 원인 분석은 롤백한 뒤에 합니다.

- 카나리 단계 에러율 1% 초과
- p95 응답 시간이 배포 전보다 2배 이상 느려짐
- 결제 실패 알림이 5분 안에 3건 이상

롤백 명령은 `make rollback SERVICE=<서비스> TO=<이전 버전 태그>`입니다. DB 마이그레이션이 들어간 배포는 코드만 되돌리고 스키마는 되돌리지 않습니다. 그래서 마이그레이션은 이전 버전 코드에서도 동작하게(컬럼 추가만, 삭제는 다음 배포에서) 만듭니다.

## 배포 권한

운영 배포 권한은 첫 배포를 버디와 함께 한 사람에게 팀장이 줍니다. payment-worker 운영 배포는 DevOps 담당 이도현 또는 팀장 김서윤이 함께 지켜봅니다.
