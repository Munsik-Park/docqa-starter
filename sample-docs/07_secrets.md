# 비밀 값 관리 규칙

API 키, DB 비밀번호, 봇 토큰, 결제 대행사 키처럼 밖으로 나가면 안 되는 값을 다루는 규칙입니다.

## 어디에 두나

- 로컬 개발에서는 서비스 폴더의 `.env`에만 둡니다. `.env`는 `.gitignore`에 들어 있어야 합니다.
- 레포에는 키 이름만 있고 값은 빈 `.env.example`을 커밋합니다.
- 스테이징과 운영의 비밀 값은 클라우드 비밀 저장소에 두고, 배포할 때 환경 변수로 주입합니다.
- 셸 설정 파일(`~/.zshrc`, `~/.bashrc`)에 키를 넣지 않습니다. 그 셸에서 실행하는 모든 프로그램이 키를 읽을 수 있기 때문입니다.

## 하지 않는 것

- 비밀 값을 Slack, 이슈, PR 댓글에 붙이지 않습니다.
- AI 채팅 도구나 코딩 에이전트에 비밀 값을 붙여 넣지 않습니다. 에러 로그를 붙일 때도 키가 섞여 있지 않은지 먼저 봅니다.
- 운영 키를 로컬 개발에 쓰지 않습니다.

## 키 교체

- 운영 키는 90일마다 교체합니다. 보안 담당이 교체 14일 전에 알립니다.
- 퇴사자가 접근할 수 있던 키는 퇴사일에 교체합니다.

## 키가 새었을 때

1. 커밋에 들어갔다면 히스토리에서 지우는 것보다 키 폐기가 먼저입니다. 한번 푸시된 키는 이미 복사됐다고 봅니다.
2. 해당 서비스 콘솔에서 키를 폐기하고 새 키를 발급합니다.
3. 보안 담당 박지호에게 알리고 `#security` 채널에 무엇이 언제 새었는지 남깁니다.
4. 새 키로 바꾼 뒤 서비스가 정상인지 확인합니다.

실수로 키를 올린 것은 징계 사유가 아닙니다. 늦게 알리는 것이 더 큰 문제입니다.
